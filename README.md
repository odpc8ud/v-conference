# ระบบขอใช้ห้องประชุม / Video Conference — สคร.8 อุดรธานี (ODPC8)

ระบบรับคำขอใช้ห้องประชุมและขอ ID Zoom/WebEx แทน Google Form เดิม
- **ข้อมูล** เก็บใน Google Sheet
- **ระบบหลังบ้าน (API)** คือ Google Apps Script (GAS)
- **หน้าเว็บ** เปิดได้ 2 ทาง: GitHub Pages (ลิงก์หลัก) และลิงก์ GAS `/exec` (ลิงก์สำรอง) ใช้โค้ดชุดเดียวกัน ข้อมูลชุดเดียวกัน

## หน้าที่มี
| หน้า | GitHub Pages | GAS (`/exec`) | ใครใช้ |
|---|---|---|---|
| ฟอร์มขอใช้ห้องประชุม | `/` | `?page=form` (ค่าเริ่มต้น) | ทุกคน |
| ตารางการประชุม | `/schedule.html` | `?page=schedule` | ทุกคน (ไม่เห็นอีเมล/รหัส) |
| จัดการคำขอ + แดชบอร์ดผู้บริหาร | `/admin.html` | `?page=admin` | เจ้าหน้าที่ (ล็อกอิน User/Password) |

## ฟังก์ชันเด่นของหน้า Admin
- **ปุ่มไอคอนคลิปบอร์ดมุมขวาล่างของแต่ละรายการ**: เปิดข้อความรายละเอียดการประชุมรูปแบบเดียวกับอีเมลแจ้งผล (ชื่อประชุม วันที่ เวลา ห้อง HOST ID Password ลิงก์ สถานะ หมายเหตุ) กด **คัดลอกข้อความ** แล้วนำไปวางใน LINE ได้ทีละรายการ
- แดชบอร์ดผู้บริหารตามปีงบประมาณ พิมพ์/บันทึก PDF ได้

## ส่วนที่ 1: Google Sheet
1. สร้าง Google Sheet และตั้งชื่อแผ่นงาน (แท็บ) ว่า **`Host_Request_Conference`**
2. ใส่หัวคอลัมน์ในแถวที่ 1 ตามนี้ (ลำดับสลับได้ ยกเว้น **`Timestamp` ต้องอยู่คอลัมน์ A**)

```
Timestamp | ผู้ขอใช้งาน | ชื่อเล่น | อีเมลผู้ขอใช้งาน | ช่องทางตอบกลับ | กลุ่มงาน | ชื่อการประชุม |
รูปแบบการประชุม (IT Support) | สถานที่จัดประชุม | วันที่ประชุม | วันสิ้นสุดประชุม | เวลาการประชุม |
จำนวนผู้เข้าร่วมประชุม | วันที่ประชุม (พ.ศ) | วันสิ้นสุดประชุม (พ.ศ) | Meeting Room | HOST ID |
Password HOST ID | สถานะการจอง | สถานะกิจกรรม | WebEx Link | อีเมลแจ้งผลส่งแล้วเมื่อ | หมายเหตุ
```
3. **ไม่ควรมีช่องว่างหน้า/หลังชื่อหัวคอลัมน์** (เช่น `" WebEx Link"`) เพราะฟังก์ชันแจ้งเตือน Telegram จะอ่านคอลัมน์นั้นไม่เจอ
4. ลบแผ่นงานที่เก็บรหัสผ่านบัญชี Zoom/อีเมล (เช่น `New Host ID`, `Old Host ID`) ออกจากไฟล์นี้ และเปลี่ยนรหัสผ่านที่เคยอยู่ในนั้น (ประวัติ Version history ยังเก็บค่าเก่า)

## ส่วนที่ 2: Google Apps Script
### 2.1 สร้างโปรเจกต์และวางไฟล์
1. เปิด Google Sheet > **ส่วนขยาย (Extensions) > Apps Script**
2. สร้างไฟล์ให้ตรงชื่อ แล้ววางเนื้อหาจาก repo
   - สคริปต์: `Code.gs`, `Auth.gs`
   - HTML: `Form`, `Admin`, `Schedule`, `Style` (ชื่อไม่ต้องมี `.html` ในหน้า Apps Script)
3. ใน `Code.gs` แก้ `ROOM_BOOKING_LINK` เป็นลิงก์ปฏิทิน/ระบบจองห้องจริง และปรับรายการ `GROUPS`, `ROOMS` ตามหน่วยงาน
4. ไอคอนแท็บของหน้า GAS ตั้งที่ค่า `FAVICON_URL` ใน `Code.gs` (ชี้ไปที่ `favicon.png` บน GitHub Pages ต้องแก้ URL นี้ถ้าเปลี่ยนชื่อ repo/ผู้ใช้) ส่วนหน้า GitHub Pages ใส่ไอคอนให้อัตโนมัติจากไฟล์ `favicon.*` ที่ root ของ repo

### 2.2 ตั้งค่า Telegram (ไม่บังคับ)
**Project Settings (ไอคอนเฟือง) > Script Properties > Add script property**
- `TELEGRAM_TOKEN` = token ของบอท
- `TELEGRAM_CHAT_ID` = chat id ของกลุ่ม/ผู้รับ

ทดสอบ: เลือกฟังก์ชัน `testTelegramConnection` แล้วกด Run ควรมีข้อความเข้า Telegram

### 2.3 สร้างบัญชีแอดมิน
1. เปิด `Auth.gs` ในฟังก์ชัน `setAdminUser` แก้ `USERNAME` และ `PASSWORD` (อย่างน้อย 8 ตัว แนะนำ 12 ตัวขึ้นไป)
2. เลือกฟังก์ชัน `setAdminUser` แล้วกด **Run** (ครั้งแรกจะขออนุญาตสิทธิ์ ให้กดอนุมัติ)
3. **ลบรหัสผ่านออกจากโค้ดทันที** แล้วบันทึก (ระบบเก็บเฉพาะ hash ใน Script Properties ชื่อ `ADMIN_USERS`)
4. เพิ่มแอดมินคนอื่น: แก้ค่าแล้ว Run ซ้ำ / เปลี่ยนรหัส: Run ด้วยชื่อเดิมและรหัสใหม่

### 2.4 ตั้ง Trigger แจ้งเตือนการประชุม
ไอคอนนาฬิกา (Triggers) > Add Trigger (Time-driven > Day timer)
| ฟังก์ชัน | ช่วงเวลา |
|---|---|
| `sendMeetingReminderToday` | 6am to 7am |
| `sendMeetingReminder` | 4pm to 5pm |

ถ้าเคยมีโปรเจกต์แจ้งเตือนเดิม (ODPC8 Meeting Notify) ให้ลบ trigger ในโปรเจกต์เดิมออก ไม่เช่นนั้นจะแจ้งซ้ำ 2 รอบ

### 2.5 Deploy เป็น Web App
**Deploy > New deployment > ประเภท Web app**
- Execute as: **Me**
- Who has access: **Anyone** (ต้องเป็น Anyone ไม่ใช่ "Anyone with Google account" ไม่เช่นนั้นหน้า GitHub จะเรียกไม่ได้)

กด Deploy แล้วคัดลอก **Web app URL** (ลงท้าย `/exec`) เก็บไว้ ใช้ในส่วนที่ 3 และเป็นลิงก์สำรอง

## ส่วนที่ 3: GitHub Pages
1. สร้าง repo ใหม่ (เช่น `v-conference`) อัปโหลดไฟล์ตามตารางด้านบน
   - ไฟล์ workflow: **Add file > Create new file** พิมพ์ชื่อ `.github/workflows/pages.yml` แล้ววางเนื้อหา
2. แก้ `site.config.json`
   ```json
   {
     "gasUrl": "https://script.google.com/macros/s/xxxxxxxx/exec",
     "roomBookingLink": "ลิงก์ตรวจสอบการจองห้องประชุม"
   }
   ```
3. **Settings > Pages > Source** เลือก **GitHub Actions**
4. แท็บ **Actions** รอ workflow **Deploy to GitHub Pages** ขึ้นเครื่องหมายถูกสีเขียว (ถ้าไม่รันเอง กด **Run workflow**)
5. เปิดเว็บที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

> GitHub Free ใช้ Pages กับ **Private repo ไม่ได้** ต้องเป็น Public (หรือแพ็กเกจเสียเงิน) จึงต้องตรวจให้แน่ใจว่าไม่มีรหัสผ่านจริง/ข้อมูลส่วนบุคคลใน repo

## ส่วนที่ 4: ตรวจสอบหลังติดตั้ง
- [ ] หน้าฟอร์ม: dropdown กลุ่มงานและตัวเลือกห้องประชุมมีรายการ
- [ ] ส่งคำขอทดสอบ 1 รายการ: ขึ้นในชีต และมีข้อความแจ้งเตือน Telegram
- [ ] หน้าตารางประชุม: เห็นรายการ (เฉพาะที่ไม่ใช่ "ไม่อนุมัติ"/"ยกเลิก")
- [ ] หน้า Admin: ล็อกอินได้ เห็นรายการและแท็บแดชบอร์ด บันทึก HOST ID / ส่งอีเมลแจ้งผลได้
- [ ] ลิงก์ GAS `/exec` เปิดและใช้งานได้เหมือนกัน

## ส่วนที่ 5: การแก้ไขโค้ดภายหลัง (ต้องอัปเดต 2 ที่)
| ที่ | ทำอย่างไร |
|---|---|
| **GitHub** | แก้/อัปโหลดไฟล์ทับ แล้วรอ Actions รันเสร็จ (อัตโนมัติ) กด Ctrl+F5 เพื่อดูผล |
| **Apps Script** | วางโค้ดใหม่ > **Deploy > Manage deployments > ดินสอ > Version: New version > Deploy** (URL เดิมไม่เปลี่ยน) |

ถ้าลืมอัปเดตที่ใดที่หนึ่ง สองลิงก์จะหน้าตาหรือการทำงานไม่ตรงกัน
ถ้าสร้าง **New deployment** ใหม่ URL จะเปลี่ยน ต้องแก้ `gasUrl` ใน `site.config.json`

## ส่วนที่ 6: เมื่อ GitHub ล่ม
**ที่ระบบทำให้อัตโนมัติ (Service Worker `sw.js`)** — ใช้ได้กับ **ผู้ที่เคยเปิดเว็บ GitHub มาแล้วอย่างน้อย 1 ครั้งในเครื่องนั้น**
1. GitHub ปกติ: เปิดหน้าล่าสุดจาก GitHub ตามเดิม
2. GitHub ล่ม/ช้าเกิน 6 วินาที/ตอบ error: เปิดหน้าจากสำเนาในเครื่อง (ข้อมูลยังดึงจาก GAS ได้ตามปกติ ล็อกอินแอดมินยังอยู่)
3. ไม่มีสำเนาในเครื่อง: พาไปลิงก์ GAS `/exec` ของหน้านั้นอัตโนมัติ (`?page=form|admin|schedule`)

**ที่ทำอัตโนมัติไม่ได้:** ผู้ใช้ที่เปิดลิงก์ GitHub ครั้งแรกขณะ GitHub ล่ม เบราว์เซอร์จะเข้าเว็บไม่ได้ตั้งแต่ต้น ไม่มีโค้ดใดบน GitHub หรือ GAS พาไปต่อได้ (GAS สั่งเปลี่ยนหน้าเองไม่ได้เพราะข้อจำกัด sandbox ของ Google) กรณีนี้ให้ประกาศลิงก์ GAS `/exec` เป็นลิงก์สำรอง หากต้องการสลับอัตโนมัติจริงทุกกรณี ต้องมีโดเมนของหน่วยงานคู่กับบริการ DNS/Cloudflare ที่ตรวจสุขภาพและสลับปลายทางให้

ล็อกอินแอดมินแยกตามลิงก์ (สลับไปลิงก์ GAS ต้องล็อกอินใหม่) ถ้า GAS ล่ม ทั้งสองทางใช้ไม่ได้ เพราะข้อมูลและ API อยู่ที่ GAS

## แก้ปัญหาเบื้องต้น
| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| หน้า GitHub ขึ้น "Failed to fetch" | ยังไม่ได้ Deploy `Code.gs` ใหม่ / สิทธิ์ไม่ใช่ **Anyone** / `gasUrl` ผิด (ต้องลงท้าย `/exec` ไม่ใช่ `/dev`) |
| Actions เป็นเครื่องหมายแดง | `gasUrl` ยังเป็นข้อความตัวอย่าง หรืออัปโหลดไฟล์ไม่ครบ ดู log ในแท็บ Actions |
| Pages ขึ้นไฟล์ดิบ/หน้าว่าง | Source ยังเป็น *Deploy from a branch* ให้เปลี่ยนเป็น **GitHub Actions** |
| ล็อกอินแอดมินไม่ได้ | ยังไม่ได้รัน `setAdminUser` หรือรันในโปรเจกต์ผิดตัว (Script Properties แยกตามโปรเจกต์) / ใส่ผิด 5 ครั้งจะถูกล็อก 10 นาที |
| `setAdminUser` ขึ้น error | ตั้ง `PASSWORD` ให้ครบ 8 ตัวอักษรขึ้นไป |
| Telegram ไม่แจ้ง | ตรวจ Script Properties ทั้งสองค่า และรัน `testTelegramConnection` |
| WebEx Link ว่างในข้อความ Telegram | ชื่อหัวคอลัมน์มีช่องว่างหน้า/หลัง ให้แก้ให้เป็น `WebEx Link` เป๊ะๆ |
| แก้โค้ดแล้วหน้า GitHub ยังเป็นของเก่า | รอ Actions รันเสร็จแล้วกด Ctrl+F5 (ถ้าเปิดจากสำเนาสำรองเพราะเน็ตช้า ให้รีเฟรชอีกครั้ง) |
| กราฟแดชบอร์ดไม่ขึ้น | โหลด Chart.js จาก CDN (jsdelivr) ไม่ได้ ตรวจอินเทอร์เน็ต/ไฟร์วอลล์ |

## ความปลอดภัย (สรุป)
- ค่าลับ (`TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID`, hash รหัสแอดมิน) อยู่ใน Script Properties ไม่อยู่ในโค้ดหรือ GitHub
- ข้อมูลหลังล็อกอิน (อีเมล, HOST ID, Password) ส่งให้เฉพาะ session ที่ถูกต้อง (หมดอายุ 6 ชั่วโมง)
- API ภายนอกเรียกได้เฉพาะฟังก์ชันที่อยู่ใน `getApiFunctions_()` ของ `Code.gs` ห้ามเพิ่มฟังก์ชันตั้งค่า เช่น `setAdminUser` เข้าไป
- หน้าตารางประชุมสาธารณะไม่แสดงอีเมล ชื่อผู้ขอ HOST ID รหัสผ่าน และลิงก์
